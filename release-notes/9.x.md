## Jackson MissingKotlinParameterException
The `jackson-module-kotlin` library no longer throws `MissingKotlinParameterExcepion` in some situations where
it previously did, as they found it wasn't the appropriate exception to throw. If you are catching said
exception and handling it in a particular way, you may need to update it accordingly. For more details, see
[the Kotlin section of the Jackson 2.20.0 release notes](https://github.com/FasterXML/jackson/wiki/Jackson-Release-2.20#kotlin-1).

## logback no longer pinned

We were previously pinning logback to version 1.5.19 in order to avoid a CVE. The CVE is fixed in newer versions, so the
pinning has been removed.

# 9.1.0

## Add ability to configure OSS Index Analyzer via project properties

The Sonatype OSS Index Analyzer now requires authentication, which has broken the OWASP builds.

From https://ossindex.sonatype.org/doc/auth-required:
> Authentication is required to use Sonatype OSS Index
> This change improves stability and gives you usage tracking and higher request limits

If your OWASP check runs in GitHub Actions using the HMPPS workflow, you most likely don't need to do anything further.
The workflow was updated to use secrets `HMPPS_OSS_INDEX_USERNAME` and `HMPPS_OSS_INDEX_PASSWORD`, while said secrets
have been set globally for the moj org (you should see them listed in the 'Organization secrets' section shown in your
repo under Settings -> Secrets and variables -> Actions). If you are using your own OWASP check workflow or are still
using CircleCI, you can see [how the HMPPS OWASP check was adapted](https://github.com/ministryofjustice/hmpps-github-actions/pull/139/files)
as an example.

The username / API token can be configured via `ossIndex.username` and `ossIndex.password` project properties. For
running locally, add a `~/.gradle/gradle.properties` file with the following contents:

```properties
ossIndex.username=<email address>
ossIndex.password=<api token>
```

# 9.0.0

## Upgrade to Dependency Check plugin utilising NVD 2.0 data feeds

WARNING: It is not recommended to upgrade to 9.0.0 if you are still using CircleCI for your security jobs. Instead, at
a minimum, you should
run [migrate-repo.sh](https://github.com/ministryofjustice/hmpps-github-actions/blob/main/migrate-repo.sh) to switch
your security jobs to github actions first.

This release upgrades the [Dependency Check plugin](https://github.com/dependency-check/DependencyCheck) from version 8
to 12.1.3.
The upgrade switches from version 1 of the [NVD feed](https://www.nist.gov/itl/nvd) to 2.0.

### Github actions

The [hmpps-github-actions](https://github.com/ministryofjustice/hmpps-github-actions) project has been changed to cache
the NVD 2.0 feeds in a custom hmpps github actions runner. To use the runner set the `nvd_feed_version` to be `2` in
your `.github/workflows/security_owasp.yml`:

```bash
yq -i '.jobs."security-kotlin-owasp-check".with.nvd_feed_version = "2"' .github/workflows/security_owasp.yml
```

This will also configure the analyze task to use the local cache directory on the runner and thus, negate the need for
an API key. The security jobs should therefore be quite quick as they don't need to download the data feed.

### CircleCI

There is no recommended upgrade path at present. It is recommended instead that you switch your security jobs to run
in github actions instead.

### Running locally

From the dependency check [README](https://github.com/dependency-check/DependencyCheck?tab=readme-ov-file#nvd-api-key-highly-recommended):
> ### NVD API Key Highly Recommended
> Dependency-check has moved from using the NVD data-feed to the NVD API. Users of dependency-check are highly
> encouraged
> to obtain an NVD API Key; see https://nvd.nist.gov/developers/request-an-api-key Without an NVD API Key
> dependency-check's updates will be extremely slow. Please see the documentation for the cli, maven, gradle, or ant
> integrations on how to set the NVD API key.

To run the dependency check locally, set an environment variable called `NVD_API_KEY` and then run

```bash
./gradlew dependencyCheckAnalyze
```

as usual.
