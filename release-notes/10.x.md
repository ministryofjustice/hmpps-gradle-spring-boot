# 10.2.0

## Unpin swagger-ui

A new version of spring doc has been released, that contains the latest swagger-ui version. Therefore there is no need
now to pin the version of swagger-ui.

Note that this change means that you no longer should have an override in `application.yml` for springdoc. So remove:

```yaml
springdoc.swagger-ui.version: 5.32.1
```

from your `application.yml`.

## Upgrade tomcat to 11.0.21

We have temporarily pinned tomcat to 11.0.21 for:

[CVE-2026-34487](https://nvd.nist.gov/vuln/detail/CVE-2026-34487):
Insertion of Sensitive Information into Log File vulnerability in the cloud membership for clustering component of
Apache Tomcat exposed the Kubernetes bearer token. This issue affects Apache Tomcat: from 11.0.0-M1 through 11.0.20,
from 10.1.0-M1 through 10.1.53, from 9.0.13 through 9.0.116. Users are recommended to upgrade to version 11.0.21,
10.1.54 or 9.0.117, which fix the issue.

[CVE-2026-34486](https://nvd.nist.gov/vuln/detail/CVE-2026-34486):
Missing Encryption of Sensitive Data vulnerability in Apache Tomcat due to the fix for CVE-2026-29146
allowing the bypass of the EncryptInterceptor. This issue affects Apache Tomcat: 11.0.20, 10.1.53, 9.0.116. Users are
recommended to upgrade to version 11.0.21, 10.1.54 or 9.0.117, which fix the issue.

[CVE-2026-34483](https://nvd.nist.gov/vuln/detail/CVE-2026-34483):
Improper Encoding or Escaping of Output vulnerability in the JsonAccessLogValve component of Apache
Tomcat. This issue affects Apache Tomcat: from 11.0.0-M1 through 11.0.20, from 10.1.0-M1 through 10.1.53, from 9.0.40
through 9.0.116. Users are recommended to upgrade to version 11.0.21, 10.1.54 or 9.0.117 , which fix the issue.

[CVE-2026-34500](https://nvd.nist.gov/vuln/detail/CVE-2026-34500):
CLIENT_CERT authentication does not fail as expected for some scenarios when soft fail is disabled and
FFM is used in Apache Tomcat. This issue affects Apache Tomcat: from 11.0.0-M14 through 11.0.20, from 10.1.22 through
10.1.53, from 9.0.92 through 9.0.116. Users are recommended to upgrade to version 11.0.21, 10.1.54 or 9.0.117, which
fixes the issue.

# 10.0.6

## Pin swagger-ui to latest version 5.32.1

[CVE-2026-0540](https://nvd.nist.gov/vuln/detail/CVE-2026-0540)
[CVE-2025-15599](https://nvd.nist.gov/vuln/detail/CVE-2025-15599)

From the CVEs:
> medium severity - CVE-2026-0540 Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting')
> vulnerability in pkg:javascript/DOMPurify@3.2.6
> CVE-2026-0540 - DOMPurify 3.1.3 through 3.3.1 and 2.5.3 through 2.5.8, fixed in commit 729097f, contain a cross-site
> scripting vulnerability that allows attackers to bypass attribute sanitization by exploiting five missing rawtext
> elements (noscript, xmp, noembed, noframes, iframe) in the SAFE_FOR_XML regex. Attackers can include payloads like in
> attribute values to execute JavaScript when sanitized output is placed inside these unprotected rawtext contexts.

and also:
> medium severity - CVE-2025-15599 Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting')
> vulnerability in pkg:javascript/DOMPurify@3.2.6
> CVE-2025-15599 - DOMPurify 3.1.3 through 3.2.6 and 2.5.3 through 2.5.8 contain a cross-site scripting vulnerability
> that allows attackers to bypass attribute sanitization by exploiting missing textarea rawtext element validation in
> the
> SAFE_FOR_XML regex. Attackers can include closing rawtext tags like </textarea> in attribute values to break out of
> rawtext contexts and execute JavaScript when sanitized output is placed inside rawtext elements. The 3.x branch was
> fixed in 3.2.7; the 2.x branch was never patched.

Note that this change causes a problem in projects protected by spring security as by default the 5.32.0 version files
are unprotected. To work around that issue set:

```yaml
springdoc.swagger-ui.version: 5.32.1
```

in your `application.yml`.

# 10.0.0

Upgrade to spring-boot [4.0.1](https://github.com/spring-projects/spring-boot/releases/tag/v4.0.1)

- If your project uses **Flyway**, you must add the Spring Boot Flyway starter dependency.
  Without it, Flyway migrations will **not run at application startup**.
- Add the following dependency:

```gradle
implementation("org.springframework.boot:spring-boot-starter-flyway")
```

See https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide for the migration guide.

## Jackson kotlin module removal

~~Spring Boot has moved to Jackson 3, so there is no need to include com.fasterxml.jackson.module:jackson-module-kotlin
any more.~~

Although Spring Boot 4.0.0 has moved to Jackson 3, Spring Docs (and especially Swagger) still use Jackson 2. See the
[Spring Docs issue](https://github.com/springdoc/springdoc-openapi/issues/3169) for more details. This therefore means
that it is still worth including the jackson kotlin module in this plugin. We also now include the jackson 3 version of
the module.
