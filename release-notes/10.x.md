# 10.3.0

## Snyk suppression for tomcat WebDAV issues

This release generates a new `.snyk` file. This file is regenerated each time gradle runs, but only overwrites the file
if the `# WARNING` line at the top of the file is still present.

This file should be committed to each repository so that it can be picked up by the snyk scan, which doesn't rely on
gradle running first.

We have suppressed:

[SNYK-JAVA-ORGAPACHETOMCATEMBED-16643259](https://security.snyk.io/vuln/SNYK-JAVA-ORGAPACHETOMCATEMBED-16643259):
Affected versions of this package are vulnerable to Allocation of Resources Without Limits or Throttling via the WebDAV
LOCK and PROPFIND XML request bodies.

The WebDAV servlet isn't enabled in our Tomcat instances, so there is no risk of this being exploited.

We have switched from trivy to snyk so no longer need to create a `.trivyignore` file.

# 10.2.1

## Note on the swagger-ui pinning removal from 10.2.0

It turns out that the latest version of springdoc can cause invalid api docs to be generated. In our case

```kotlin
  val moreInfo: Any? = null
```

generates

```json
  "moreInfo" : {
"type": "null",
}
```

For now, therefore, I would suggest avoiding the spring doc upgrade and instead for now pinning to swagger-ui `5.32.2`.
See https://github.com/ministryofjustice/cmd-api/pull/388/changes for an example. Also see the discussion in slack
at https://mojdt.slack.com/archives/CTLQ5TCNN/p1776435600279719 for more information.

- If your project uses **Flyway**, you must add the Spring Boot Flyway starter dependency.
  Without it, Flyway migrations will **not run at application startup**.
- Add the following dependency:

```gradle
implementation("org.springframework.boot:spring-boot-starter-flyway")
```

See https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide for the migration guide.

## Jackson kotlin module removal

~~Spring Boot has moved to Jackson 3, so there is no need to include com.fasterxml.jackson.module:jackson-module-kotlin
any more.~~

Although Spring Boot 4.0.0 has moved to Jackson 3, Spring Docs (and especially Swagger) still use Jackson 2. See the
[Spring Docs issue](https://github.com/springdoc/springdoc-openapi/issues/3169) for more details. This therefore means
that it is still worth including the jackson kotlin module in this plugin. We also now include the jackson 3 version of
the module.
